## What live proof caught that tests did not

re-export chain, so `harness: claudeCode()` could not be committed); a

## Known limits carried out of this wave

1. **`claudeCode()` can narrate an effect it never produced.** Asked to author
   an automation it created nothing and said "Done." Root-caused as
   structural, not prompt plumbing (`docs/verification/wave2-eproof-fix/
   D2-D3-followup-brief.md`): our register is appended to the SDK's own
   co-trained coding-agent preset, the box snapshots its tool list once (no
   mid-turn `find_tools`), and the box path has none of the anti-invention
   machinery `vendo()` and `instant()` grew from live measurement. The fix is
   a harness-independent checks floor for chat turns — a follow-up lane, not a
   prompt line.
2. **E3's `vendo()` half stays unproven.** In-process harnesses have no
   workspace tool family: `workspaceBash` shipped in wave 1 with zero callers
   and `vendo()` never touches `turn.workspace`. Classified
   CONTRACTED-AND-DROPPED at decomposition (`docs/verification/
   wave2-eproof-fix/PARKED.md`); one follow-up lane owns the six descriptors,
   their reviewed risk labels, and the re-run.
3. **≤5s time-to-skeleton missed at 6.1s median** — accepted for this wave
   (design §16 marks the bar "stands until re-measured"), residual is the
   plan-call model seat, a product decision.
4. In-box `Task` subagents run auto-allowed with no hire receipt (per-subagent
   cost is unobservable in the SDK).
5. Body-less `DELETE` still needs `content-type: application/json` (the global
   CSRF floor; relaxing it is a security decision with a sweep).
6. Records-seam asymmetry: the harness-state row is readable but not
   deletable through the public records door.
