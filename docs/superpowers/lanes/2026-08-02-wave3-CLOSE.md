# Wave-3 close record — multi-party (the Cloud half)

**2026-08-02.** Lanes G (orgs + `can()`) and H (sponsorship + org policy),
built, verified, integrated onto wave-2's landed head, live-proven, and
independently checked. Written for whoever picks this up next: what is true
now, what is deliberately not, and the traps that cost this wave a round.

Companion documents: the frozen shapes are `2026-07-30-build-contract.md` §9
(six amendments made during this wave, each marked in place); the laws are

## What this wave makes true

- **A team can share an app, and Vendo never learns the org chart.** The host
  answers "who is this, and which teams are they in?" on every request and
  every unattended run, through one callback on the auth preset. That answer
  is used and thrown away: the independent check traced both places a run
  context is written to disk and confirmed each uses an explicit whitelist
  that excludes memberships. There is no table, column, or cache that could
  hold one.
- **The only multi-party rows Vendo stores are grants** (app → principal →
  level), plus sponsorship state, which is Vendo-specific and not an org
  chart.
- **One permission function, one shared rule set.** `can()`'s pure half —
  principal grammar, level ordering, path rules — lives in core with a
  conformance kit mounted by both implementations, so a rule that moves on
  one side reds the other's suite.
- **Sharing writes need a Cloud key; enforcement does not.** `can()` is OSS
  and key-blind: an unkeyed deployment behaves identically, it simply has no
  shares to enforce. No capability booleans, no entitlement protocol.
- **Org admins can tighten what their members' agents may do, and can never
  loosen it** — arithmetic in the clamp, not a promise. A host `block` is
  never talked down, and THE LAW (§12: destructive and external actions are
  never unattended) survived both lanes untouched.
- **An automation runs as a named person**, stops loudly the moment that
  authority lapses, and waits in the app for the next editor to take it on,
  approving as themselves. Approvals stay strictly self-subject.

## The pattern that mattered most: the Cloud-store family

Four separate defects, one root cause — **logic that belongs at the permission
door was living in the local store's SQL/routing layer**, so Vendo Cloud's own
default hosted store behaved differently from BYO Postgres:

1. promote refuses on the hosted store (loud; BYO-only, still open);
2. org policy was silently inert there (now announced once per deployment);
3. the grant grammar was unguarded — the identical malformed request was
   refused on Postgres and **accepted** on hosted;
4. grant rows carried no refs, so the lookup query could never read them back
   on a generic-record adapter: a share wrote a row and granted nothing.

The contract now says it plainly: validate at the door, and grant rows carry
`refs { app_id, principal }`. When reviewing anything in this half, ask which
store shape you proved it on.

## Verification, and what it cost

Eleven independent passes across the two lanes plus three wave-level ones.
Every pass found something real. The findings that mattered were all **silent
failures** — none visible in tests, none visible on screen:

- a viewer could roll the team's app back (undo was gated at viewer);
- a concurrent promote deleted the winner's ownership grant, leaving the
  promoter locked out of a half-moved app;
- a paused run could be released under a *different* person's identity after
  the app changed hands;
- a hosted-store fault reported a failed read as a successful revoke;
- the person-share field encoded free text verbatim as a subject, so the grant
  matched nobody — and share-implies-promote had already moved the app;
- a query flag let a stranger confirm a team app exists, at HTTP 200.

Two blockers were pure consumer-voice defects: the Share dialog told a bank's
customer to set an environment variable, and pasted a line of TypeScript at
them. **Build, tests, typecheck and lint were green the entire time.** Nothing
we gate on could see any of this. What caught them was a fresh reader holding
the consumer-voice law, and a real browser.

## Known limits — ship with these, they are recorded not forgotten

- Hosted store: promote refuses (a hosted promote door is Cloud-side work).
- Served org apps relay only `content-type`, so redirects break; the CSRF JSON
  floor refuses HTML form posts on them; and the adoption card cannot appear
  on a served surface (no card slot, no renderer path) — all behind the
  experimental served-apps flag.
- Raw host error text still reaches the adoption card and the automation
  resume door; the 402 body still carries the developer sentence over the wire.
- Org ids and user subjects share one column with no discriminator — a host
  invariant, documented where the code depends on it; a discriminator is a
  schema-train change.
- `docs/principals-and-orgs.md` still describes the pre-wave-3 org model, and
  neither `memberships` nor `resolvePerson` is documented host-facing. **A docs
  pass is the first follow-up.**
- No `vendo_apps_fork` agent tool: the model can direct a person to fork but
  cannot do it (product call).
- The Playwright UI suite has pre-existing failures; `pnpm test` does not run it.
- Wave-2's two load-sensitive flake classes (harness-system-prompt timeout, the
  redteam fixture host) — theirs, documented in their close record.

## Traps that cost this wave a round each

- **A clean-looking auto-merge spliced both lanes' versions of one function**,
  leaving one lane's call outside the other's error guard and silently
  reinstating a fixed bug. It compiled; only the other lane's own regression
  test caught it. When two lanes edit one function, read the merged body.
- **Two agents in one worktree is not safe even with disjoint file ownership** —
  cross-package tests resolve from `dist`, so one agent's build landing inside
  the other's suite run produces failures that vanish in isolation. Give
  concurrent fix agents separate worktrees.
- **A test that cannot fail is worse than no test.** Two were found this wave
  (an assertion over an array that stayed empty; an unscoped spy reading
  another phase's calls). Every gate ships a red-green pair, and the red half
  must be watched failing.
